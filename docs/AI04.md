## 🔴 二、结果会错

**Bug 2 — `reader.c:30` 行号数错了（`-n` 必然错）**
`match_action` 里 `reader->line_number++`，但 **`match_action` 只在"命中"时才调用**！所以 `line_number` 数的是**命中数**，不是**物理行号**。

```
文件:  boot ok / hello / boot again      (boot 在第 1、3 行)
lrg -n boot 期望:  1:boot ok   3:boot again
你实际输出:        1:boot ok   2:boot again   ❌
```
**行号要"每读到一行就 +1"（不管命不命中）**，不能放在 `match_action` 里。得挪到"行凑齐"的地方。

**Bug 3 — `reader.c:55` match 传错了长度**
```c
memcpy(&reader->line[reader->end], ...);
reader->end += length;
if(match(reader->line, length, ...))   // ❌ 传的是"这一段"的长度
```
应该传**整行的总长 `reader->end`**。当一行**跨块**（残行 + 本段）时，`length` 只是最后一段，**匹配会漏**。（单块内、无残行时 `end==length` 才恰好对，所以你没发现。）

**Bug 4 — `main.c:23` 没有 stdin 支持**
`options.file_number == 0` 时（省略 FILE），循环一次不跑，直接 `return error`（=1）。**题目要求读标准输入**，这块**完全没实现**。

**Bug 5 — `reader.c:119-121` `-c` 输出三个错**
```c
if(reader->reader_options->count_only && reader->line_number != 0){
    printf("%s:%d", name, reader->line_number);
}
```
- ❌ **总带文件名前缀**——单输入时题目要求**只输出数字**（不带文件名）；
- ❌ **没有 `\n`**（`printf("%s:%d", ...)` 结尾没换行）；
- ❌ **0 命中时整个跳过**——但题目要求 `-c` **即使 0 也要输出 0**。

**Bug 6 — 多文件普通输出没文件名前缀**
`match_action` 只打印行本身。**多文件时**题目要求 `文件名:行内容`（`-n` 时 `文件名:行号:行内容`），你没加文件名前缀。

## 🟠 三、输出/IO 隐患

**Bug 7 — 混用 `printf` 和 `write`（`reader.c:33/40`）**
行号用 `printf`，行内容用 `write`。**stdout 被重定向/管道时**，printf 走缓冲、write 直出，**顺序会乱**（和之前 `-c` 那次同款坑）。统一用 `write`（或统一用 printf + 冒号）。
